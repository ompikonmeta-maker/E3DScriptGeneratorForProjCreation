# Output format

Every command below is backed by a fact in RULES.md. Do not emit any other command.
Files: ASCII, line ending per `project.lineEnding` (default CRLF), final line ending present.
`$*` starts a comment line. Comment text is free; **command lines must match exactly** (tests compare
non-comment lines only — see `fixtures/` and `tools/reference_generator.py`).

## 1. ZIP layout (`output.split = perDiscipline`)

```
<packageName>.zip
├── 00-README.txt
├── 00-TEAMS/<teamsFile>                     e.g. ZRF-00-TEAMS-ADMIN.mac
├── <discFolder>/<b1File>                    e.g. 02-L-ZRFPIP/ZRF-02-L-B1-CREATE-DB-MDB-ADMIN.mac
├── <discFolder>/<b2File>                    e.g. 02-L-ZRFPIP/ZRF-02-L-B2-SITES-DESIGN.mac
├── <discFolder>/<b3File>                    only when the row has zones
├── 90-REFERENCE/<refFile>                   when output.includeReference and referenceDbs not empty
├── 99-FIXUP/<fixupFile>                     when output.includeFixup
├── <registerFile>                           when output.includeRegister (e.g. ZRF-E3D-Register.xlsx)
└── config.json                              when output.includeConfig
```

One `<discFolder>` per row of the row attribute that has at least one cell, in `urutan` order.
`perStep`: replace the per-row files with `B1/<prefix>B1-CREATE-DB-MDB-ADMIN.mac`,
`B2/<prefix>B2-SITES-DESIGN.mac`, `B3/<prefix>B3-ZONES-DESIGN.mac` containing all rows in order, each
row block introduced by a comment line `$* --- <row desc> ---`. MDB positions are unchanged.

## 2. Header block (every .mac)

```
$* ===========================================================
$* <TITLE>
$* Generated by E3D Setup Generator - <project.code> - <project.target>
$* <one or more note lines>
$* ===========================================================
$*
```

B3 files: the first note line is
`$* WARNING: NEW ZONE after navigating to a site is not yet tested (facts sec 9).`

## 3. Files

### 3.1 00-TEAMS (Admin)
```
CREATE TEAM <kode> DESC '<desc>'          one per team row with existing = false, row order
SET TEAM <kode>                           only for new teams that have anggota
TADD <user>                               one line per member (documented form, fact §2)
```
With `output.includeExistingTeamsBlock`: a commented block for `existing = true` teams
(`$* CREATE TEAM …`, `$* SET TEAM …`, `$* TADD …`).
Members of existing teams are assumed to be members already (read from Export Config). Adding members
to existing teams is out of scope for v1.

### 3.2 B1 per row (Admin)
```
CREATE DB <db> <type> ACCESS <access> CLAIM <claim> DBNO <dbno> DESC '<desc>'     one per cell
$*
SET MDB <mdb>
ADD <db> <pos>                                                                   one per cell
```
`'` inside DESC is not allowed (validation error V01 on the source text).

### 3.3 B2 per row (Design)
```
NEW SITE <sepDiscipline> DB <db of first cell>
NEW SITE <sepGroup>[ DB <db>]
NEW SITE <site>[ DB <db>]
…
$*
SAVEWORK
```
Order and DB-clause rule: SPEC §4 steps 5–6. Expected result for ZRF Piping:
`fixtures/zrf/02-L-ZRFPIP/ZRF-02-L-B2-SITES-DESIGN.mac`.

### 3.4 B3 per row (Design)
```
<site>                       navigate (§9 — untested)
NEW ZONE <zone>              one per zone of that site
…                            next site block; sites without zones are skipped
$*
SAVEWORK
```

### 3.5 90-REFERENCE (Admin)
```
SET MDB <mdb>
ADD <db> <pos>                          active rows, list order
$* ADD <db>   <- <note>                 inactive rows, in their list position
```

### 3.6 99-FIXUP (Admin)
```
SET MDB <mdb>
CURRENT <db> <pos>                      all generated DBs in order, then active reference DBs
```
Header note: `Use only if the MDB order is wrong. A DB that is not in the MDB stops the macro: ADD it first.`

When rows target different MDBs (SPEC 3.3), B1/99 emit one `SET MDB` block per MDB.

## 4. 00-README.txt

```
<project.code> (<project.name>) - E3D SETUP PACKAGE
Generated <YYYY-MM-DD HH:mm> by E3D Setup Generator. Target: <project.target>.

PREPARATION (Admin, SYSTEM)
 - Delete old DBs of this setup if re-running. Check the MDB is empty and no old DB files remain.
 - Nobody else logged in to the project.

STEPS (command macros only)
 00-TEAMS -> per row: B1 (Admin) -> re-enter DESIGN -> B2 sites (Design) -> B3 zones (Design)
 Rows in order: <list of folders>
 Then 90-REFERENCE (Admin). 99-FIXUP only if the MDB order is wrong.

WARNINGS
 - B3: NEW ZONE after navigating to a site is not yet tested (facts sec 9).
 - <every validation warning, one per line>

KNOWN ISSUE
 Random '(43,41) Unable to open DB ... MCD:6 The handle is invalid' while creating DBs.
 Note the DB, delete it in Admin if broken, recreate it, continue.

COUNTS
 Teams new/existing: n/n  DBs: n  Sites: n  Separators: n  Zones: n  Reference DBs: n
```

Run-order table (README, screen 6, register "Setup Steps"):

| Step | What | File | Module | Check |
|---|---|---|---|---|
| P | Delete old DBs, MDB empty, nobody logged in | — | Admin | Databases list |
| 0 | New teams | 00-TEAMS | Admin | Team count |
| B1 | CREATE DB + ADD to MDB | per row | Admin | DBNO, MDB positions |
| — | Re-enter DESIGN | — | Design | New DBs visible |
| B2 | Separators + sites in display order | per row | Design | Model Explorer = Site Order |
| B3 | Zones | per row | Design | Zone count |
| ↻ | Repeat B1–B3 per row, in order | — | — | — |
| 90 | Reference DBs to MDB | 90-REFERENCE | Admin | MDB member count |
| 99 | Fix MDB order (optional) | 99-FIXUP | Admin | Only if wrong |
